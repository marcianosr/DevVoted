# Changelog
All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## Unreleased
- **A config states its size as a number, and its version as dots**: a config used to draw one coloured block per slot, so a 16-slot config spent a quarter of its chip on blocks nobody counted past about four, and the biggest sizes crowded the name off the row entirely. A config now carries a single **weight block** — the slot count as a figure, edged in the size colour — which takes the same room at 16 slots as at 1, so every row lines up and the name always fits. The colour still means exactly what it did: green at 1 slot, yellow at 2, orange at 4, purple at 8, with the drifting rainbow edge from 8 up. Beside the name, the version you are running is now a **row of dots**, one per version the config can reach, filled up to the one you hold — so "three of five, two left to buy" is something you see rather than something you read off `v3/5`. Every chip shows the ceiling now, including mid-run, where it used to show only the rung you were standing on. And **every list that names a config now draws it as a chip**: the shop's build and offers, the prep build, the final build on the game-over screen and the list you pick from when a gate peels you. A config looks the same wherever you meet it, instead of being a bordered chip in some places and a bare name with tags in others. The poll screen's build panel keeps its plainer line, because a chip crowds out the status dot and the presses that sit beside it.
- **New config: git rebase -i — decide which poll you meet first**: the order a gate deals its five polls has always been the daily seed's business, which quietly decided a lot for you. **Cold Start** doubles the gate's *first* answer, **Overclock** quadruples it and then runs hot on everything after, **Cache** pays more the longer you stay right in one category, and **Dependabot** counts correct answers in a row — every one of them cares where a poll sits, and none of them let you do anything about it. **git rebase -i** (4 slots, 128 KB) does. On the prep screen it lists the gate's five polls **by category**, each next to the coverage you already hold there, and moves any of them up or down the queue. Put React first and Cold Start fires ×2 on the category you are best at; push Java to the back and Overclock's ×0.5 tail lands on the poll you were going to miss anyway. **The order locks the moment you answer** — this is a bet placed before you read a single question, and knowing the category is not knowing the question. It reveals **only** the categories: option counts, which polls take more than one answer, and the next gate's mix all still belong to **Prefetch**, which stays the better buy if what you want is to see. The two do not need each other, and rebase never reorders anything but your own run — the seed everyone climbs is untouched, so a posted result stays comparable. Worth knowing before you buy it: on its own it changes no number at all. It is only worth slots next to a config that cares about position, and in a build with none of them it is four slots of sightseeing.
- **Storage plans are earned by filling them, not by renting the one below**: the shop's plan rack has always hidden the rungs past the next one behind `????`, and the only way to uncover one was to rent the rung under it — so the ladder revealed itself to anyone with the rent, in the order they paid. A rung now opens once a run of yours has **actually held the cap below it**: fill 512 KB and the 1 MB rung appears, fill 1 MB and the 2 MB rung does. The free cap and the 512 KB rung are always on the shelf, so nothing about a first run changes. This is the same moment the game already tells you about from the other side — storage stops at your cap, and a clear that pays past it burns the difference — so the burn that used to be pure loss now also opens the rung that would have held it. A masked card says what opens it and how close you have come ("opens at 512 KB held · best 384 KB") instead of printing `????` twice, and the meter's tick at your cap is the line you are filling toward. **The mark is your account's, not the run's**: a rung you opened in a run that later died stays open in every run after it, and the best you have ever held is remembered even after you spend back down to nothing. What a rung *costs* has not changed at all — the select press still refuses a bill you cannot cover, and dropping to a cheaper rung is still always allowed.
- **New gate rule: 451 Unavailable For Legal Reasons**: a gate can now arrive with its answers redacted. On a gate carrying 451, the window's **first three polls** each show two of their answers as `?????` instead of text, and **4 KB buys one back** — the same price every time, however many you unseal. A sealed answer is still pickable, so guessing blind is a real play rather than a dead end: you might recognise the question well enough to gamble, or spend 8 KB to be sure. Two answers on every poll always stay readable, so no poll is ever a coin flip, and which ones are sealed has nothing whatsoever to do with which one is right — `?????` never points at the answer. The linter refuses to cross out a sealed answer, since telling you a hidden option is wrong would be a cheaper way of reading it than paying; buy it back first and the linter will touch it. 451 never turns up alongside 300 Multiple Choices or 404 Not Found, which already make a poll hard to read. It can share a gate with 403 Forbidden, which freezes the linter and the peek — but never the buy-back, because a sealed answer you are forbidden to read would be a trap rather than a rule. Like every gate rule it is named on the stake receipt before you walk in, and everyone climbing that day meets the same one. Whatever you gambled on, the answers are all named in full on the reveal afterwards.
- **A miss costs more the deeper you are, and the last two gates ask for more**: a wrong answer used to bleed exactly half of what a correct one pays, at every gate. That share now **starts at half and climbs three points a gate**, reaching 0.86 at the Champion, so the same mistake that costs 0.5 at Pallet costs 11.2 at the summit instead of 6.5. The reason is arithmetic you could feel: the coverage a gate demands grows far faster than what an answer pays, so a late miss had quietly shrunk from a sixth of the opening gate to a fiftieth of the last one, and deep gates were asking only that you keep answering. They now ask that you be right: the accuracy you need to break even rises from 33% at the start to 46% at the end. Everything else about the bleed is unchanged, and both halves still ride your own build, so a stacked build keeps earning more and losing more per mistake. **Elite now demands 300%** (was 290) and **the Champion 375%** (was 340).
- **New config: Garbage Collection — a miss can pay you back**: failing a gate makes you free slots by dropping configs or minifying them, and until now that removal returned nothing at all: the config left and took its price with it. **Garbage Collection** (2 slots, 64 KB) turns the peel into a sale. Every config you **drop** to settle the quota refunds exactly what selling it in the shop would have, so shedding a 256 KB config hands back 128 KB toward rebuilding, and the repair screen prices each row next to its remove button so you can see which config is worth the most on the way out. **Minifying pays nothing** — the config is still installed, so there is nothing to collect — which turns the two ways of paying a peel into an actual choice instead of a formality: keep half the effect, or take the money. It is priced by the same shelf the shop sells from, so WTFPL still voids every refund and Freemium still halves them, and it pays for its own removal if it is the config you decide to let go. It cannot save you from the miss that ends a run: when a peel is bigger than your whole build the run is over before the repair screen opens, and nothing is refunded. Worth knowing before you buy it: in a climb where you never miss a gate, it does nothing at all.
- **The first gate cannot end your run**: **Pallet**, gate 0, is now the calibration gate. It still asks for its 3% coverage, but missing it **peels nothing** and cannot kill you, so the first failure in a run teaches the loop for free: you read back the five answers you just missed, shop, and run the same gate again on five fresh polls. Before this, a lean opening build could die on the very first gate, which is a harsh way to learn that a config is also your hit points. From **Boulder**, gate 1, onward the peel applies exactly as before. The only way to end a run at Pallet is to stand in front of it with an empty build, which could never pass anyway. The Gates dex now says Pallet peels "none" rather than printing a zero.
- **Which audits a gate carries is drawn fresh every day**: gate 4 used to be 424 Failed Dependency and gate 9 the storage leak, in every run forever, so once you had seen a gate you had seen every version of it there would ever be. The count is unchanged (one audit from gate 3, two from gate 8, three from gate 11), but which rules fill those slots is now drawn from staged pools, seeded on the date. **Gate 3 still opens on 402 Payment Required and gate 12 still closes on its handcrafted three**, so a climb begins and ends on ground you know, and 410 Gone stays fixed to Elite, so its deepened peel is still a number you can look up. Everyone climbing on a given day meets the same gauntlet, which keeps a posted result comparable, and nothing is hidden inside a run: the stake receipt names every audit before you walk into the gate, and the Dex publishes the pools. A gate you missed keeps its audits on the retry. A gate never draws two rules that do the same job (the three paid-action audits never stack, and no two of the five that knock a config offline share a gate), and 300 Multiple Choices never draws alongside 408 Request Timeout, because a clock that runs out voids the mirror rather than beating it. The first five audited gates always teach five different rules; deeper gates can bring an earlier one back, now stacked with something new. Two audits scale with depth rather than repeating: the clock tightens from 3 polls at 30s to 5 at 20s by the Champion, and 410 peels more at the summit than at Elite. In the Dex, the Gates tab names what a gate is certain to carry and states the rest as a count ("draws 2 of 13"), while the Audits tab lists every rule with the gates it can reach.
- **Dependabot pays for a clean streak, not for time**: it used to roll 1 in 3 on every gate clear, so an eight-slot, 256 KB config could sit through five gates doing nothing at all. It is a counter now, and its row on the poll screen shows the countdown: **five correct answers in a row** upgrade a random config in your build for free, then the count restarts. **A wrong answer starts it over, and so does a failed gate**, which means the config is worth what your accuracy is worth rather than a flat rate for showing up. An upgraded Dependabot asks for four in a row instead of five. Which config the merge lands on is still the dice's business, and it still ignores the category coverage the shop would demand for that same upgrade, so a merge can hand you a level you never earned. Answering at 70% it pays about four upgrades a climb, which is what the old roll averaged; at 90% it pays nine or more. It also wants a build worth upgrading: a narrow build runs out of configs that can still take a level, and the merges stop until you widen it.
- **The Coverage config is gone**: it doubled all coverage for 2 slots and 64 KB, which is what AGENTS.md already did for 8 slots and 256 KB. The same effect at a quarter of the price meant nothing ever had a reason to buy the bigger one, and an eight-slot config sat dead in every shop roll. Coverage is the one that left rather than AGENTS.md, because its name also collided with coverage the score. AGENTS.md is now the only ×2, with Intellisense's ×1.5 at 4 slots as the rung under it, and Coverage drops out of the configs a new account starts with.
- **The build panel's total now counts the configs it is listing**: a config whose effect only fires under a condition — Cold Start on the gate's opener, a Focus config on its own category, Cache on a warmed one — used to advertise its multiplier on its own row while contributing nothing to the **Total** underneath, so the panel could read "Cold Start ×2" over "Total ×1" on exactly the question where the ×2 was about to be paid. The total is now worked out for the poll in front of you, by the same arithmetic that scores the answer, and a config an audit has taken offline no longer counts toward it.
- **A gate's retry cost is quoted in the unit it actually takes**: the forecast reads in configs, as a range when the sizes in your build make it one ("peels 1 config" on an opening build, "peels 1–3 configs" once a big config sits next to small ones), because which ones go is your pick. The repair screen itself reads in **slots**, which is what the debt really is and what minifying pays down, so the two screens no longer quote the same number under two different nouns.
- **Every line about a config now shows the config**: the gate clear's rewards list named "Unit Tests" and "Moore's Law" in plain text, its "what changed" list left off the version that had just changed, and an audit reported passing without saying which config was covering for it. All three now carry the config's chip — its size, its name, and the version it is running. And when Dependabot's roll upgrades something, the line names the config it fired on *and* Dependabot as the cause, instead of leaving a levelled-up config sitting there unexplained.
- **Rebuild says why it is off, and the slot bar stopped spanning the screen**: with WTFPL installed the whole roster is already on the shelf, so **Rebuild offers** greys out — it now says "Config list exhausted!" on hover rather than just refusing. The build's slot bar was stretching the full width of whatever panel held it, spending a screenful to say how four slots are divided; it is bounded now, so the proportions read at a glance.
- **A config's colour now tells you how much room it takes**: every config used to wear one of five colours standing for a family (focus, defense, risk, amplify, economy), a grouping that named nothing you could act on: it never changed a check, a payout, a shop roll or a gate, and two configs sharing a colour had no more in common than two that did not. Colour is now keyed to **size**, so the edge on a config's weight block matches the number of slots it fills: green at 1 slot, yellow at 2, orange at 4, purple at 8 (with pink and red waiting for the two larger sizes nothing uses yet). A build bar, a shop row, a prep list and a Dex chip all now answer "how big is this" the same way, in the same colour, and the Dex legend keys sizes instead of families. Minify recolours as well as reshapes: halving an 8-slot config down to 4 slots drops it to the 4-slot colour, so the saving is visible at a glance. An undiscovered config in the Dex gives up its size rather than its family, which does tell you a little more than before (size is price), but still never which config it is. Every screen that draws a config carries the colour: the configure and shop build bars fill each segment in its config's size colour (a minified config keeps its dotted edge and drops a colour rung, matching the width it just gave up), every config chip on prep, answer, shop, reward and the run summary leads with its size, and the Configdex's slot groups head with a bar in the group's colour.
- **The slot bar is proportional again, and the way back to the shop is not a price**: a config's block on the build bar is as wide as the slots it fills, so a two-slot config reads as twice a one-slot config instead of one more equal square, and every slot still open is drawn as its own dashed cell you can count. The prep footer's "← change · 256 KB" now says **Back to shop**: it was quoting your balance beside a button, which read as a fee for going back.
- **The build says what it is counting**: the section header used to read "BUILD 1" over a bar captioned "4 of 4 slots", which left one Prefetch sitting under four blue blocks meaning anything you liked. Both measurements are now named lines under the bar: **configs 1** and **slots 4 / 4**. A revealed line on the gate list also names what revealed it, so "categories · javascript 5" carries a **Prefetch** chip rather than appearing to be something the gate told you. And the "today's 5 polls are ready" strip lost its Start button: the same button sits in the footer, and two of them made the screen look like it was asking twice.
- **The prep screen counts the window down, and the draw reads as one block**: the polls line reads "0 / 5 answered" rather than "answer all 5", so a window you came back to mid-way says where you are in it. Under it, indented, sit the two things you can learn about those same polls — **type** and **categories** (plus the next gate's, when a config reveals them) — with the gate's **target** above the block and its **audits** below. The gate's position on the ladder came off the list: the header and the swatch track above it were already saying it twice.
- **Prefetch counts the window for you**: it now reads out three lines instead of one. **Poll type** says how many of the gate's remaining polls take more than one answer ("3 single · 2 multiple"), which is what partial credit and your pick budget both hang on. **Options** lists how many answers each of those polls puts in front of you, poll by poll, in the order they come ("4 · 4 · 5 · 6 · 4"), so the wide poll that thins a guess from one in four to one in six is something you see coming instead of something you meet. **Categories** stopped listing the draw poll by poll and counts it instead ("javascript 2 · react 1"), biggest first, because where to aim is the decision you are making on that screen. Without Prefetch all three lines still read **???**.
- **A crossed-out answer is struck through, and stops being pickable**: the option a linter eliminates now wears a line through it, and its row is no longer a button. It used to dim and label itself "crossed out" while still taking the click, so you could spend a lint and then answer with the option you had just paid to remove.
- **The gate you are about to run reads as one list**: the prep screen's Requirements, Audits and Prefetch sections merged into a single list, headed by the gate's name and its unearned swatch (a dashed square, since you have not cleared it yet). Its rows are **gate** ("4 of 12"), **target** (the coverage demand, with a bar that fills to it and keeps a lighter tail for anything past it), **polls** ("answer all 5"), **poll type**, **audits** and **categories**. Poll type and categories read **???**: the first has no seller yet, the second is Prefetch's to sell, and both sit there regardless, because knowing the window has a shape you could have bought is part of what makes buying it a decision. A suppressed audit still shows on the list, struck through and marked "reported passing".
- **New config: yarn.lock — the shop's padlock is bought now**: locking an offer used to be a built-in control that arrived at gate 2 and held exactly one offer. It now ships with **yarn.lock** (1 slot, 32 KB): while it is in your build, every offer on the shelf carries the padlock — 16 KB locks one, rebuilds skip it, and every later shop leads with it until you install it or press **release**, which is free and refunds nothing. Lock as many as you like; each pinned offer occupies one of the shelf's slots, so freezing your whole shop is possible and entirely your own doing. The pins belong to the lockfile: sell yarn.lock, or lose it to a gate peel, and every lock releases with it. WTFPL still retires the padlock, since the whole roster is already on the shelf. And the Gates dex no longer promises "lock" at gate 1 — no gate hands it over anymore.
- **Coverage reads against what the gate asks, and shows the spill**: the prep screen's coverage requirement and the gate clear's coverage total both carry a small bar that fills to the demand and keeps a lighter tail for everything past it, so a window that overshot reads as overshoot instead of as one more green figure. The requirement lines sit one to a line now (name left, reading right, the way the bills under them already did), and the section is called Requirements.
- **The prep and shop screens tidy up**: the slot track moved under the Build heading instead of sitting in a band of its own above both columns, so the room your build fills sits next to what is filling it; "On a clear" stopped spanning the full width and joined the column with the audits, requirements and bills. In the shop, the storage plan opens on the rung you are actually on (it used to scroll it half off the left edge) and wears the gate's colour instead of a fixed green.
- **Storage plans start smaller and cost a lot more to climb**: the free cap is now **256 KB** rather than 512, and the rungs above it double instead of creeping: 512 KB, 1 MB, 2 MB, 3 MB, 5 MB, 10 MB. Every rung's rent went up two to three times (the first upgrade is 32 KB a gate, not 16; the 1 MB rung is 96), because the old bottom of the ladder was a rounding error against a gate clear and nobody had to think about it. The free cap no longer holds a perfect late clear, so the plan is a real prerequisite for saving toward a slot instead of a formality. **And a rung you cannot pay for is no longer for sale**: the upgrade press refuses while the next rung's bill is more than your balance and tells you both numbers, since the only thing buying it could do was drop you back a gate later with your overflow burned. Dropping to a cheaper rung is always allowed. If a plan you are already on outruns your balance, the shop keeps its door shut until you drop to one you can afford, the same way it does for a build that is over capacity.
- **Buying and cashing a slot are rows now, not floating buttons**: the two buttons that used to sit adrift under your build (and jostle each other once both were available) are full-width lines in the build list itself, priced on the right with a single **+** or **−** press. A slot you have bought but not filled reads "Slot 5 · empty" with its cash press beside it, so the empty room in your build is something you can see rather than infer. Refusals ("Every slot is filled — uninstall or minify first") now sit on the line instead of being squeezed into a column between the buttons. The run-start screen's archive slots got the same treatment.
- **An armed purchase labels its price**: confirming an upgrade used to put a bare yellow figure next to the effect chips, where "96 KB" (what it costs) sat beside "+96KB" (what it will pay) meaning two completely different things. The price now sits on its own line under the description, labelled **price** for an upgrade and **sell price** for an uninstall.
- **Config effects read the same on the poll screen as in the shop**: opening a config's row mid-poll now badges its numbers (×1.25, +8 KB) the way every shop row does, instead of printing them as flat text.

- **An upgrade now tells you what it buys, and a locked one says why**: arming an upgrade in the shop used to show you `v1 → v2`, which is the badge you were already looking at. It now states the sentence the config will read at its next level ("JavaScript polls earn 1.5× coverage.") and puts a chip on every number that moves, so `1.25× → 1.5×` or `+32KB → +64KB` is on screen before you spend. An Upgrade press you cannot use says so on hover instead of just greying out: "Unlocks at 5% Java coverage, you have 0%." The requirement was always there; it simply had nowhere to appear, because the only place it was written was a confirmation you could not reach. And every config row in the shop now describes itself at the level it is actually running, so a `.js` upgraded to v2 stops advertising the v1 rate.
- **The shop shelf can sell you a version of a config you already own**: about one shop in eight now rolls a levelled copy of something in your build onto the shelf, at the shelf's normal price. Buying it swaps the config you own for the better one instead of taking a second slot, and (this is the point) it asks for **no category coverage**, so it is the way past a Focus upgrade you have not earned yet. It cannot be kept for the next shop, and an owned config still never appears as a plain second copy. Offers carry their version beside the name now, the same badge your build rows wear.
- **A/B Test switches arms mid-poll, and the switch counts for the poll you are on**: the ⇄ press used to live only in the shop, which meant a poll in the wrong category was answered on whichever arm you happened to leave the shop with. Open a config's row on the poll screen and the press is there, free and unlimited; the arm you switch to scores the answer you are about to give. Buying A/B Test buys the right to retune per question, not per shop.
- **Config rows on the poll screen open up to say what they do**: the build panel used to show a name, a dot and a figure, and keep the config's actual effect to itself while you answered. Every running row is now a fold: tap it and you get the config's sentence, plus its arm switch where it has one. They start closed, so the panel still reads as a status board rather than a manual.
- **The build panel says what is running, and names what is broken**: the lonely count in the panel's header now reads "2 running" with the green dot beside it, matching the language of the lines under it. When an audit takes a config offline, the warning above the question names the casualty ("`.js` is offline this gate.") rather than telling you one of your configs is down and leaving you to find it; the config's own row no longer squeezes its name off the line to fit the audit code, which moved into the fold. The line about how many answers a gate holds now credits the config that bought you that information, `.length`, and the poll's category chip wears the gate's colour instead of a fixed purple that meant nothing.
- **Storage reads the same everywhere, and says how close the ceiling is**: the shop used to print "1024 KB" directly above a storage plan calling the same number "1 MB". There is one formatter now, and everything past a megabyte says MB. Every balance on screen carries a small bar showing how much of your cap you are holding, so the ceiling is visible before a clear overpays it rather than after. The gate clear shows the balance you came from next to the one you landed on ("512 KB → 560 KB"), since the clear is the one moment the number moves. Hovering any part of the storage plan (held, cap, bills, the bar, the next rung, drop, upgrade) now explains what it is. The buy and cash slot lines sit side by side instead of stacked.

- **The run opens on a dealt hand, and you make the first pick**: starter stacks are gone. The run now deals you **five configs**, seeded to your day and always holding at least one category multiplier, and picks **none** of them for you. **Two are marked as a suggested opening**, which is advice rather than a selection: **one config is all you need to play**, so the shortest possible opening is tap one, press Start. Nothing in a build is ever locked or handed to you. The deal reads as one checkable list: picking a config no longer moves it to another column, it just fills in, and a config too big for the room left dims where it sits. An over-capacity build is the only thing that blocks the start. The Gamble / Safe start / Category spread cards were deleted rather than reworked, because the interesting objects were always the configs underneath. Buying slots from the archive moved below the deal, out of the opening question's way.
- **New config: A/B Test**: a config that ships one of two reward arms at a time — arm A pays ×1.25 on all coverage, arm B pays +8 KB of storage per correct answer. A ⇄ press on its shop row switches arms for free, and the row's own text always names the arm that is live and the one waiting. Each arm is deliberately no stronger than the specialist config it mimics; what you are buying is the right to retune every shop.
- **New config: Cache**: correct answers now warm the category they were asked in, for the rest of the run. Each poll pays up to +25% more coverage per earlier correct answer in its category, topping out at double after four. One wrong answer in a category flushes everything it had cached — invalidation is the price of the speed-up. While a category holds nothing, the config's row says so: "cache is cold here".
- **The storage plan is a rack of cards you scroll**: every rung of the ladder sits in the shop as its own card — your rung opens centered wearing a "current" tag, each card names its cap in large type and what it costs ("costs 96 KB a gate"), and a select press moves you. Rungs more than one step above yours read **????** until you climb to the rung below them, so the top of the ladder is something you reveal rather than read on day one. A drop warns what it burns on its own card, in amber, and a rung billing more than you hold refuses with both numbers on it. Under the cards one bar still shows the KB you hold against your cap, with a dashed stretch sized to exactly what the next rung would add, now captioned in plain words: "1.2 MB held · 819 KB free · 2 MB cap · +1 MB on 3 MB". The slot band above the build hands its bar over and reads as a count instead: "18 of 24 · 6 free".
- **Four new audits, and the ladder reshuffles to fit them**: **404 Not Found** (gate 5) hides every poll's category, so which of your configs is about to pay is yours to work out; **429 Too Many Requests** (gate 10) rate-limits you to one paid action for the whole window, linter or peek; **426 Upgrade Required** (gate 11) takes your *lowest*-level config offline, the mirror of 409 taking your highest; **413 Payload Too Large** (gate 12) leaks 8 KB a poll for every slot past the twelfth, so a wide build pays to carry itself. Gates still run one audit from 3, two from 8 and three from 11 — the roster they draw from is now fifteen deep instead of eleven, so fewer of them repeat.
- **Every audit now goes by its HTTP status**: Cost Overrun is 402 Payment Required, the shop-closing Read-only is 405 Method Not Allowed, the clock is 408 Request Timeout, the mirror is 300 Multiple Choices, and the four that knock a config out are 409, 424, 502 and 503. The class tells you what kind of trouble it is before you read the rule: 4xx means the gate changed the rules on you, 5xx means part of your build is down. What each audit does is unchanged.
- **The build band shows who is running at a glance**: the rail above the poll now sits boxed in its own border, headed by a count of the room and the action — "4 of 12 slots · 2 running", with the running dot echoed right beside it. Each config carries a corner dot: yellow while it pays on this question, gray while it sits one out, red when an audit downed it. A config sitting the poll out fades and refuses the cursor while keeping its full box, so the shape of your build never changes — only how much of it lights up.
- **The shop shelf leads with what a config does, not what it costs**: every offer now states its effect on the top line, right of the name, so the shelf reads without opening a single row. Its size, what installing it would do to your per-answer take, and its price all drop to a quieter second line underneath, price on the far right.
- **The archive can open a run wider**: the start screen now sells slots from your archived storage, at double what the shop charges — 32 KB for a fifth slot, 64 for a sixth, and on up the same ladder. What you buy here counts on that ladder, so the shop picks up on the rung above. Nothing caps it but the price: eight slots costs 480 KB of archive, and twelve costs more than a perfect climb banks. Change your mind before you press Start and an empty slot hands straight back for what it cost.
- **Slots are bought, and storage has a ceiling again**: gates no longer widen your build on a schedule, and there is no more rent on extra slots. Every run opens on **four slots** and buys the rest off the build track itself: the hatched stub at its end prints the next slot's price and buys it on a press, up to 24 — 16 KB for the fifth, then 32, 64, 128, 192, 256 and on up, doubling every second rung. Both presses take two taps — the first spells the deal out on the line under the track, the second spends — so nothing is bought by a stray tap and the price reads on a phone, where there is no hover. The empty box beside the stub **cashes a slot back** for exactly what that slot cost, which turns width you were never going to fill into a draft or an upgrade; the ladder never rolls back, so the next slot you buy costs the rung above the last one you bought, and buying-then-cashing always nets zero. - **Pipeline width comes from gates, and the shop rents up to four extra spots on top — the storage cap is gone**: the storage plan is retired, and with it the KB ceiling, the insolvency downgrade and every "512 of 768 KB stored" bar in the game. Storage is simply money: gate clears pay it, the shop spends it, and **nothing caps what you can hold**. The cap was cut rather than moved because it was never doing the job it was there for — mid-run you might sit on 320 KB against a 1 MB ceiling, which is not a decision — and the pressure it was meant to apply is already applied continuously by what the shop charges. A ceiling only bites at the top; a drain bites all the way along. Bundling the cap with your pipeline's width onto one row had a second cost: the plan was selling two things at once and you could not tell which one the bill was for. **In its place, two sources of room that do not overlap.** Every run opens on **4 spots** and reaches **8, 12, 16 and 24** by clearing gates 1, 4, 7 and 10 — the same free width at the same depth for every run, whatever it is holding or spending. **And a new shop section, Extra spots**, rents four steps on top of that: **+1, +2, +3, +4**, at a flat **8 KB a gate per spot**, so +3 spots is simply three times +1 with nothing to work out. It is the grade that used to be called *legendary*, and eight spots of your pipeline deserves to look like it cost that. Minify it and the ring goes: the dotted edge that says "this one is halved" is the more useful of the two, and the ring would paint straight over it.

The mark *is* the definition: a nibble is four bits, so the nibble glyph is four cells, and more cells means rarer with nothing to memorise. The old rarity colours are gone with the old names — a rare config's red bar used to sit in the same shop row as the red **Uninstall** press and mean something unrelated — and the four grades wear a plain ramp instead: **grey, blue, purple, gold**, bit up to byte, on the squares and on the grade's name at the end of the row. The little squares in front of its name *are* the price: count the cells and you know the room. A config too big for the room left dims where it sits, so you find out before you tick it rather than after. That makes the grade ladder mean something for the first time; a byte used to cost the same one slot as a bit, so being rare bought you nothing but a bigger number. Now a byte is a genuine dilemma wherever you meet it — early it literally cannot fit, and late it costs you most of your build. **KB is untouched**: it still buys offers, upgrades, rebuilds, locks, extensions and the git tag, at the same prices as before, and it never buys width. Spots come from clearing gates and, past a byte, from renting them. Keeping the two apart is the whole point: if money bought room, and room bought score, and score bought money, a lucky run would spiral into twenty configs and an unreadable score reveal. **Minify** is the new pressure valve — halve a config's spots and halve what it gives, one way only. Beside a poll the chips stay, because there they carry the will-pay / did-pay grammar.

Your picks sit badged against the key — "expected" in green, "you picked" in green or red depending on whether you should have — with the also-rans stepped back. The poll's explanation lands here too, at the moment you actually want to know why. Answering correctly in a row has always paid 10% more per answer up to double, and the ceiling was never stated anywhere. It reads as a property of your build rather than a rule of the gate, because configs that sell you more headroom are coming, and this is the number they will move.

Gates behind you read solid, the gate you're running fills as you answer its five polls and wears a pale outline so you can always find where you are standing, and the rest sit dimmed ahead. Hover or tap a pip and it names that gate's badge and where you stand: "gate 3 · Thunder Swatch · Running now · 3 of 5 answered". The caption above the bar names the gate you're currently in ("Boulder gate · 1 / 12") in that gate's own colour, so the HUD calls it what the shop, the reward screen and the swatch you're climbing for all call it.
- **The gate tells you what a mistake costs**: the pipeline header now names the stake inline — "a fail peels 3" — and turns red when a failed gate would take your whole build, which from around gate 4 it will if you are running lean. Deep gates peel more configs than shallow ones, so a narrow pipeline goes from risky to sudden-death without warning; now there is one.
- **The shop stops pretending**: hovering an offer you can't buy no longer draws it into your pipeline. Previously a config you couldn't afford, or had no free slot for, still appeared as a ghost row in a slot that didn't exist yet, which read as if it had been installed. Now only offers you can actually install preview, and the chip's own price tag and tooltip say why the others can't. Those price tags are also smaller and the offer row has room to breathe, so a tag no longer lands on the next config's name.
- **Pipeline slots are numbered**: the load-out list counts down its slots in the margin — 1, 2, 3 — including the empty ones and the locked rung at the bottom, so "slot 4" on the unlock row is visibly the fourth slot. Each row's detail now hangs off its status mark instead of its config chip, giving the list one clean thread down the left, and the rarity word is gone from the rows (the chip's border already says it). Hovering a bench config no longer prints "click to add" inside your pipeline — the previewed row is the button, and saying so mid-pipeline read as if the config were already installed.
- **Storage reads as free space**: the HUD leads with what you have left to spend — a big "328 KB free" over a bar of what's committed, with "184KB of 512KB used" underneath — because headroom is what you budget against in the shop, and anything earned past the 512KB cap is discarded. Every storage number carries its KB, so no figure on screen is a count of something unnamed. (The old help text still claimed a 1 MB cap; it doesn't.)
- **Your build is the whole checklist**: gates no longer carry a built-in correct-answer demand — only your configs' checks judge you, with Unit Tests owning the escalating correct-count. In exchange, a cleared gate pays by how deep you are and how well you answered: 32 KB × the gate number, scaled by your correct answers — gate 1 tops out at 32 KB, gate 5 at 160, growth stops at gate 12, and a 0-correct clear pays nothing. A pipeline with nothing installed has no checks to pass, so it can never clear a gate, which is why losing your whole build now ends the run.

Multipliers still at ×1 read dim so the stats that actually move are the ones that glow, and a color key under the bench names the four rarities.

Under it, open by default, sits the config's story in plain sentences: the demand first ("Gain coverage in 2 categories"), then the payoff ("Then all coverage earns **×1.5**" — the numbers glow), a linter's fee in red, and the rarity. Tap the chip to fold a row to its one-liner and tap again to reopen; the same view fits desktop and mobile. Code Coverage's row no longer prints "steady" while your streak is clean — no news is good news. The linter acts from its own row: its "use 8KB" button replaces the poll card's old "Run linter" button. The answering screen's pipeline section is headed "Your pipeline" with the slots counted underneath, the same heading the run setup screen uses; the poll's category header is smaller, and the colored line under it is gone. The shop's chips stay as the click-to-sell/upgrade target in their row; only the answer review keeps its boxed badges.

Your load-out rows carry their verbs the same way: an **Upgrade** button — shown only when the config can actually level — that wears the legendary prismatic ring the moment its coverage requirement is met, and **Deinstall** with its refund; no more hidden sell/upgrade popover behind the chip. Coverage badges line up every category this gate's polls came from ("CSS +1.3%", "JavaScript +1.1%", …). And your answers sit right on the screen: one tight row per question with its PASS/PART/FAIL badge and the coverage it earned, folding open to the choices on a tap — the "Review answers →" button is gone.
- **A clearer run setup screen**: all offered configs now sit in a single list beside your pipeline — no more separate steps. The pipeline shows how many slots you've filled, and the gate reward, multipliers, and failure penalty read as one compact line of stats underneath your picks.
- **Build your own starting pipeline**: Unit Tests is no longer pre-installed and locked. Every run begins with 3 empty slots, and you pick all 3 starting configs yourself — the run won't start until every slot is filled. Only your picks judge you — the gate demands what your configs demand, and payouts follow how well you answer; Unit Tests is now an ordinary pick that pays +32 KB per cleared gate, and like any other config it can be sold, stripped, or drafted later from the shop.
- **Every config now has a price — its check**: installing a config adds its own demand to the gate, and the gate fails if any demand goes unmet. The linters (ESLint, Stylelint) turn crossing out an answer into a pledge: a poll you linted must be answered correctly. IndexedDB wants 3 correct answers per gate and its income dries up at 320 KB per run. Code Coverage snaps if you miss two polls in a row. Intellisense now boosts all *coverage* ×1.5 (instead of storage) and wants coverage in two categories each gate. Coverage doubles your coverage gains (instead of paying storage) and only asks for +1%. Cold Start doubles your very first answer of the gate — as long as it lands. Copilot remains the only config with no strings attached.
- **Unit Tests levels up for storage**: each level costs 32 KB × the level bought (L2 = 64 KB) and buys both halves — +32 KB payout per level on clear, +1 correct answer demanded. Its automatic climb-escalation now stops at 4 of 5, so an un-upgraded Unit Tests always survives one miss at any depth; only bought levels can demand a flawless 5-poll day. Every upgradable config caps at level 5, and a focus config's demand now clamps to how many polls of its category actually appear — an upgraded `.js` asks for every JavaScript poll in a thin window, never an impossible count.

Rebuilding the shop's offer costs more and climbs faster (4 KB, then doubling each time). The linter now starts cheap at 8 KB but doubles every time you use it on the same poll, so leaning on it to clear a single poll gets expensive fast. Each pipeline config is a row with a PASS / SKIP / FAIL badge, its chip, its description, and the coverage or storage it earned — a skipped focus reads "no css poll in this gate", a failed one "needs 1 correct ts, got 0". A "Steps: N passed, N failed, N skipped" line sits up top and the run totals (storage + coverage) at the bottom. - **The game tells the truth about gate demands**: requirement text now shows the escalated target for deeper gates (e.g. "Requires 3 correct answers"), matching the progress counter.

- **Focused gate screens**: after a gate clears or fails, your answers tuck behind a one-line summary bar ("Review your 5 answers · 2 partial · 3 incorrect") — one click opens the full poll-by-poll review.
